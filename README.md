# localmix — два локальных сервера llama.cpp для «смеси моделей»

Поднимает рядом два маленьких сервера, чтобы OMP мог отправлять ограниченные задачи
исполнителю, а замкнутые тяжёлые — узкому ризонеру, не трогая frontier-модель.

| роль | модель | порт | контекст | лицензия | зачем |
|---|---|---|---|---|---|
| воркер | MiniCPM5-2B Q4_K_M | 8091 | 32k | Apache-2.0 | инструменты, 131k контекст, агентные задачи |
| ризонер | VibeThinker-3B Q4_K_M | 8092 | 40k | MIT | математика/код с проверяемым ответом |

Порты 8091/8092, а не 8080: 8080 — дефолт `~/Bonsai-demo` и порт автообнаружения
llama.cpp в OMP. Эти два сервера объявлены в `~/.omp/agent/models.yml` явно
(`local-fast`, `local-think`), поэтому Bonsai и они не мешают друг другу.

## Запуск

```bash
./start.sh          # оба сервера; ждёт /health и печатает результат
./start.sh fast     # только MiniCPM5-2B   → http://127.0.0.1:8091
./start.sh think    # только VibeThinker-3B → http://127.0.0.1:8092
./stop.sh           # остановить (по pid-файлам в run/)
tail -f logs/fast.log
```

Скрипт идемпотентен: если порт уже отвечает `/health`, второй сервер не стартует.

## Одна команда на всё: `lm`

`lm` — единая точка входа (сам файл в этом каталоге, симлинк в `~/.local/bin/lm`, поэтому
доступен из любой директории). Отдельно помнить `start.sh`, `stop.sh` и `think.sh` не нужно.

| команда | что делает |
|---|---|
| `lm` | интерактивное меню (fzf) — то же, что открывает клавиша `SUPER + SHIFT + L` |
| `lm status` | состояние серверов: порты, имя модели, занятая VRAM |
| `lm start` | поднять оба сервера (`lm start fast` / `lm start think` — по одному) |
| `lm stop` | остановить |
| `lm restart` | перезапустить оба |
| `lm ask "вопрос"` | спросить воркера; `lm ask --clip` — взять текст из буфера обмена |
| `lm think "задача"` | замкнутая задача ризонеру; `lm think --clip` — из буфера |
| `lm tabs [--domain]` | разобрать вкладки Zen (проект `../zen-tabs`) |
| `lm eval` | замер SemIf на 144 авторских пунктах |
| `lm logs [fast\|think]` | хвост лога сервера |
| `lm panel <аргументы>` | то же в плавающем окне Omarchy (для кнопок меню) |
| `lm up` / `lm alive fast` | тихая проверка, 0 = жив — используется в условиях меню |
| `lm notify-status` | уведомление рабочего стола с состоянием |

Скрипты `start.sh` / `stop.sh` / `think.sh` остаются рабочими: `lm` их вызывает.

## Кнопки в Omarchy

Раздел **Local models** в меню Omarchy (`SUPER + SPACE` → Local models) и клавиша
`SUPER + SHIFT + L`. Пункты — в `~/.config/omarchy/extensions/omarchy-menu.jsonc`,
клавиша — в `~/.config/hypr/bindings.lua`.

- Пункты появляются и исчезают по состоянию: когда серверы подняты, есть «Stop all» и
  «Restart all», а «Start» скрыт; когда остановлены — наоборот.
- Вопросы идут через буфер обмена: скопировал текст → «Ask worker» → ответ оказался
  в буфере и пришёл уведомлением на рабочий стол.
- Длинный вывод (вкладки, логи, замер) открывается в плавающем окне `foot` 875×600
  по центру: правило Omarchy для app-id `org.omarchy.terminal`. Терминал по умолчанию
  (WezTerm) под это правило не подпадает и открыл бы обычный тайл — поэтому именно foot.

## Переменные

| переменная | по умолчанию | смысл |
|---|---|---|
| `FAST_GGUF` / `THINK_GGUF` | файлы в `models/` | подменить файл модели (например, на Q8-квант MiniCPM) |
| `FAST_CTX` / `THINK_CTX` | 32768 / 40960 | контекст; главный рычаг по VRAM |
| `FAST_PORT` / `THINK_PORT` | 8091 / 8092 | порты |
| `LLAMA_SERVER` | `~/Bonsai-demo/bin/cuda/llama-server` | бинарь llama.cpp (CUDA-сборка, libcublas 13 рядом) |

## Почему именно эти флаги

- `--min-p 0` — **обязателен для MiniCPM5-2B**. Дефолт llama.cpp 0.05 отрезает
  маловероятные токены, которыми модель выходит из цикла повторений. Вендор
  подтвердил причину в обсуждении модели.
- `--chat-template-kwargs '{"enable_thinking": false}'` — без него модель уходит в
  `<think>`, тратит бюджет и возвращает **пустой** `content` (замерено: 220 токенов,
  `finish_reason=length`, content `''`). С флагом — 30 токенов и прямой ответ.
- `--temp 1.0 --top-p 0.95 --top-k 0` — рекомендованный режим обоих чекпойнтов
  (`top-k 0` = выключен, что соответствует `top_k=-1` из карточек моделей).
- `-fa on -ctk q8_0 -ctv q8_0` — KV-кеш в 8 бит: вдвое меньше VRAM при почти
  неизменном качестве; без `-fa on` квантизация KV не работает.
- `--jinja` — chat-шаблон из GGUF; без него у MiniCPM5 нет доступа к формату
  вызова инструментов.
- `-ngl 99` — все слои на GPU.

## Ресурсы

Обе модели вместе занимают меньше половины карты; узкое место — не модели, а
десктоп: браузер и редактор держат 3–5 GB из 12 GB. Если свободной памяти мало,
уменьшай `FAST_CTX`/`THINK_CTX` (KV-кеш — главный потребитель после весов), а не
квант.

## Ризонер как инструмент, а не агент

```bash
./think.sh "Сколько целых от 1 до 600 делится на 7, но не на 3?"   # → ANSWER: 57
echo "задача" | ./think.sh                    # или со stdin
THINK_RAW=1 ./think.sh "..."                  # весь ответ, а не только последнюю строку
THINK_MAX=4096 ./think.sh "..."               # бюджет новых токенов (по умолчанию 8192)
```

Скрипт сам собирает запрос к 8092, просит завершать строкой `ANSWER: <value>` и печатает
только её (или `UNSUPPORTED: …`, если задаче не хватает данных).

**Почему не субагент OMP.** VibeThinker-3B не обучен tool-calling. Как только ему
показывают схемы инструментов, он начинает галлюцинировать вызовы
(`<function name="edit"> … <function name="yield"> …`), тратит на это минуты и засоряет
ответ. Замерено: через субагента — **4 мин 34 с** и мусор в выводе; тем же вопросом через
`think.sh` — **11 с** и чистая строка. Поэтому агента `local-thinker` больше нет.

## Замер SemIf на этой машине

```bash
./semif-eval.sh                 # 144 авторских пункта через llama.cpp-бэкенд на CPU
./semif-compare.py GOLD OURS REF   # метрики + согласие с предсказаниями авторов
```

Результат прогона 23.09.2026 (Qwen3.5-4B Q4_K_M, CPU, 20 потоков): accuracy 0.7986,
mean family balanced accuracy **0.8102** против опубликованных **0.813** (BF16, GPU),
согласие решений строка-в-строку с предсказаниями авторов — **93.8 %** (135/144),
386 с на 144 решения (**2.7 с на решение**).

Метрика сверена: на закоммиченных предсказаниях авторов тот же счётчик даёт 0.8132
против опубликованных 0.813, поэтому сравнение корректное.

Вывод: качество открытой реплики воспроизводится на кванте и CPU, но скорость —
батчевая. Интерактивный режим потребует Torch/CUDA и ~8.5 GB VRAM, то есть карту
целиком вместо двух наших серверов.

## Связь с OMP

```bash
omp models find minicpm                 # local-fast/minicpm5-2b
omp models find vibethinker             # local-think/vibethinker-3b
omp -p "..." --model local-fast/minicpm5-2b
omp bench local-fast/minicpm5-2b local-think/vibethinker-3b --profile generation
```

Роли `fast_worker` и `thinker` в `~/.omp/agent/config.yml`. Агенты получают модель
через `model: "@fast_worker"` в своём frontmatter.

## CORS

`llama-server` отвечает `Access-Control-Allow-Origin: <Origin>` и 200 на preflight —
любая страница или расширение в браузере может обращаться к модели напрямую, без шима.
Обратная сторона: любая открытая вкладка тоже может опрашивать ваш сервер. Не держите
в промптах секретов.

## Что эти модели НЕ делают

- VibeThinker-3B не умеет tool-calling и не должен быть оркестратором: он решает
  замкнутые задачи (математика, самодостаточный код), а контекст для него собирает
  агент с инструментами.
- MiniCPM5-2B — исполнитель, а не судья: не ставь его на решения, где нужна
  калиброванная вероятность (для этого есть Jev-класс, см. `~/Projects/jev-decision`).
- MiniCPM5-2B **не знает мир** и плохо говорит по-русски. Проверено: «столица
  Австралии» → «Брисбен» / «Сydney» / «Вальпарамина» при temperature 1.0, 0.7 и 0.3.
  Модель рассчитана на en/zh и на работу по заданному контексту.
- **Ни одной из двух моделей нельзя давать право записи в файлы.** 22 сентября
  2026 воркер на MiniCPM5-2B с инструментом `write` перезаписал `start.sh` и
  `README.md` этого проекта списком переменных — то есть уничтожил файлы, которые
  читал. У `local-worker` теперь нет `write`; если он понадобится, пусть пишет в
  отдельный файл в `~/tmp`, который человек проверяет до переноса.
